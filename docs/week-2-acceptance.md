# 第二周验收 · 本地审阅闭环

日期：2026-10-06。范围按 Day 8–14 已交付功能及本次整合验收，不代表公开上线、生产可靠性或真实模型效果验证。

## 本次补齐

1. **前两步独立运行**：整理并确认简历证据，选金融 / 数据或保持不确定，生成证据方向报告。无需职位正文、profile 或模型密钥。
2. **6 个有版本的探索模板**：数据分析、BI、数据工程、财务分析、风险分析、投资分析。每个模板有 3 个主题，标签是项目内编辑示例，不是雇主要求或经过研究校准的能力标准。
3. **逐主题解释**：显示兴趣来源、原文、行号、相关标签、表述类型以及未知项。每个主题只计一次，不因反复出现关键词加分；采用固定模板顺序，没有匹配率、资格结论或录用概率。
4. **确认后才能进入下一步**：报告不自动选岗位。用户将岗位加入草案，编辑并确认后，只有目标岗位文字进入随后新职位的偏好；证据行不会被自动升级为 `profile.json` 的事实或模型经历证据。
5. **私人报告下载**：仅本页保存，刷新清空；可下载含原文但不含备注的 JSON。下载文件不是 profile，暂不支持导入。
6. **直接打开文件的说明**：相对资源路径让 HTML 文件也能显示界面，文件模式明确提示启动服务并使用 localhost，禁用后端操作，不假装已经连接。
7. **一条命令完成离线验收**：`python verify_week2.py` 运行后端、前端语法和状态回归。需要 Node.js；测试仅使用合成数据 / 模型替身和本机临时端口。

## 报告技术与边界

`POST /api/direction-report` 使用现有同源 / 自定义头保护。服务器重新解析同一简历并通过 `review_resume_evidence` 校验 fingerprint、全部条目、类型、标签子集与编辑结构。浏览器发送明确的已审阅标志，但该标志只是用户声明，不是服务器证明用户真的进行了核查。

`direction_report.py` 对保留且有标签的行做模板集合交集。课程、学习中、仅提到、否定分别显示。类型有分歧时保守处理：原文或用户分类为否定时不升级；课程 / 学习中 / 提及改成实践不能新增实践证据，而显示待核对；用户可以将实践降级为课程等。备注不参与解释、计数或输出报告。正向表述与否定表述同时命中时两者都展示，用户需核对适用的经历和时间。

没有线索表示“当前证据未覆盖”，不表示缺乏能力。只支持金融 / 数据的证据报告；其他大类保留原快速探索目录，并明确不使用用户的证据编辑。没有兴趣选择时展示六个模板，不从简历推断偏好。规则不能完整理解语义、掌握程度、否定范围、经历主体或资格，报告不是完整推荐引擎。

简历、证据、勾选声明、大类或 profile 改变时，旧报告与方向确认失效。响应受来源 / 编辑 / 请求版本保护；连续请求的旧响应不会覆盖新报告或误开启按钮。目标文字在请求期间修改也会忽略旧结果。
